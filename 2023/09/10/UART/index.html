UART通信基础知识

UART 看起来只有几根线，但遇到乱码时，问题可能在电平、接线、帧格式、时钟，也可能在上层数据编码。把这些层次分开，排查会快很多。

下面先确认接口，再手工解一个字节，最后解释波特率误差和常见故障。波形图根据明确的比特序列绘制，文末脚本验证位序与帧检查；这些是教学示意，不是实物逻辑分析仪采样。

UART 简介

UART 是 Universal Asynchronous Receiver/Transmitter，负责并行数据与异步串行数据之间的转换。异步意味着两端没有共享时钟线；接收端通过起始位重新确定一帧的采样时间，然后按自己的时钟继续取样。

常见非反相 UART 逻辑信号在空闲时为高，起始位为低，停止位为高。RS-232 等接口还涉及不同的电气层，不能把接插件上的电压直接当作 MCU 的 UART 引脚电平。

两根信号线之外，还要确认什么

TX 接对方 RX，普通非隔离连接需要公共参考地。VCC 是否连接取决于供电设计，不能按名字直接相连。

“两根线”通常指 TX、RX 两根数据信号线。如果只监听目标输出，可以仅连接目标 TX、接收器 RX 和参考地；RTS/CTS 硬件流控又会增加信号线。

接之前先确认逻辑电平，例如 1.8 V、3.3 V 或 5 V，以及输入是否容忍对方输出电压。USB 转 TTL UART、USB 转 RS-232、USB 转 RS-485 的线缆不能因为都叫“串口线”就混用。RS-232、RS-485 是相关电气接口体系，UART 关注的起始位、数据位等并不能替代收发器。

UART 数据帧

115200 8N1 的意思是：115200 baud、8 个数据位、无奇偶校验、1 个停止位。常见 UART 每个符号承载一位，因此这里波特率数值等于比特率；有效字节速率还要扣除帧开销。

部分 8N1 中的长度 作用
Start 1 bit 从空闲高电平进入低电平，建立采样起点
Data 8 bit 通常低位先发，依次 D0 到 D7
Parity 0 bit 8N1 没有这一位；8E1/8O1 会加入校验
Stop 1 bit 在规定时间保持停止状态

其他配置是否支持 5～9 位数据、1.5 或 2 个停止位，要看具体外设。停止位并非必须至少两位，也不一定表现为低到高跳变：如果最后一个数据位已经为高，线路可以连续保持高电平。

奇偶校验能发现什么

偶校验要求数据位和校验位中 1 的总数为偶数，奇校验则要求为奇数。上面的 0x53 有四个 1，偶校验位为 0，奇校验位为 1。

单个比特翻转会改变奇偶性，两位翻转则可能互相抵消。因此 parity 能发现部分传输错误，不能纠错，也不能替代上层 CRC、帧序号或消息认证。

接收端会消费起始、校验与停止信息，再把有效数据交给软件；原笔记的“丢失起始位”应理解为协议处理时剥离这些控制位，而不是通信发生了丢包。

波特率误差为什么会累积

起始位只在一帧开头提供同步。之后每过一位，发送和接收时钟之间的差异都会积累。如果接收采样点逐渐滑到相邻 bit，即使前几位正确，后面的数据和停止位也可能出错。

图示意接收端位时间偏长时采样点向右漂移；误差方向相反时向左漂移。

用理想模型粗看，若停止位中心在起始边沿后的 9.5T，累计偏移应小于半个位宽。但真实系统还有起始检测量化、采样策略、上升下降时间和噪声余量，不能把这个粗略界限直接当作器件指标。也不能笼统说“两端允许相差 10%”。Analog Devices 的时钟精度分析讨论了这些误差预算。

收发步骤放到外设里看

发送时，软件把字节写入发送寄存器或 FIFO，硬件加入控制位，再由移位寄存器逐位输出。接收端完成采样和帧检查后，将数据放入接收寄存器或 FIFO，由中断、轮询或 DMA 搬走。

这也解释了三类不同错误：

错误 说明 优先检查
Framing error 停止位采样不符合预期 波特率、位宽、反相、噪声
Parity error 奇偶检查失败 奇偶配置、数据干扰
Overrun 接收缓冲来不及被软件读走 中断延迟、FIFO/DMA、应用处理速度

Overrun 发生时，线路上的波形可能完全正确。不断换波特率并不能修复软件读取不及时的问题。

乱码排查顺序

  1. 确认供电、参考地和逻辑电平，检查 TX/RX 有没有接反。
  2. 查看空闲状态与边沿，判断是不是 UART、是否反相，而不是立刻穷举所有波特率。
  3. 测量多个短脉冲，推测基础 bit 时间，再用连续多帧验证；一个脉冲可能跨越多个相同 bit。
  4. 核对数据位、parity、停止位和流控。
  5. 保留原始十六进制字节，再判断它是文本编码还是二进制协议。终端显示乱码不一定代表 UART 解码失败。
  6. 若开始正常、持续发送后丢字，继续查看 overrun、缓冲区和应用读取策略。

UART 解决字节怎么传，上层协议还要解决消息从哪开始、长度是多少、是否完整、属于哪次请求。分析串口日志时，这两部分最好分别记录。
